# v1.1 提出時の Play Console 申告変更点(データセーフティ / IARC / アプリのコンテンツ / 掲載文)

作成: 2026-09-27。v1.0 の申告(`store_listing.md` §3〜5)からの**差分**だけをまとめる。
v1.1 で追加されるのは「みんなの図鑑」(写真共有、Supabase)/ ウィッシュの発売通知(端末内ローカル通知)/ メモ・場所 / 作品名タグ / 新メーカー2社。
外部送信が発生するのは「みんなの図鑑」だけ。通知・メモ・場所・タグは端末内で完結し申告に影響しない。

## 1. データセーフティ(アプリのコンテンツ → データセーフティ)

### 概要の設問

| 設問 | v1.0 | v1.1 |
|---|---|---|
| ユーザーデータを収集または共有しますか? | いいえ | **はい** |
| すべてのユーザーデータは転送時に暗号化されますか? | — | **はい**(Supabase / GitHub とも HTTPS) |
| ユーザーがデータの削除をリクエストする方法を提供していますか? | — | **はい**(アプリ内: 長押し→共有を取り消す。メール: 匿名IDを添えて info@ へ → 匿名IDに紐付く全データを削除) |
| アカウント作成の有無 | なし | **なし**(匿名サインインはユーザーが認識するアカウントではないので「アカウントを作成しない」で申告。ただし匿名IDは「デバイスまたはその他のID」として申告) |

### データの種類ごとの回答

| データの種類 | 収集 | 共有 | 収集は任意か | 目的 | 一時的な処理か |
|---|---|---|---|---|---|
| 写真と動画 → **写真** | はい | いいえ | **任意**(共有を選んだ写真のみ) | アプリの機能 | いいえ(保存する) |
| アプリのアクティビティ → **その他のユーザー生成コンテンツ** | はい | いいえ | 任意 | アプリの機能 | いいえ |
| デバイスまたはその他の ID → **デバイスまたはその他の ID**(匿名ID) | はい | いいえ | 任意(共有機能を使った場合のみ生成) | アプリの機能、不正行為の防止・セキュリティ | いいえ |

- 「共有」はすべて**いいえ**。理由: (1) 他ユーザーへの表示はユーザーが自分で選んで公開する UGC で、Google の定義では第三者への共有ではない。(2) Supabase / Google(Gemini・Vision)への送信は**サービスプロバイダへの転送**で、定義上「共有」に該当しない
- **収集しないもの**(v1.0 と同じ「いいえ」のまま): 位置情報 / 個人情報(名前・メール等) / 連絡先 / 財務情報 / 健康 / メッセージ / 音声 / ファイルとドキュメント / カレンダー / アプリの情報とパフォーマンス / ウェブ閲覧 / 広告ID
- 「アイテムのメモ・回した場所」は自由入力だが端末内のみ。**収集に含めない**
- 「写真」は image_picker で取得するが、共有を選ばなければ端末内のみ。**共有を選んだ写真だけが収集対象**(だから「任意」)
- 「デバイスまたはその他のID」を選んだ場合、目的に「不正行為の防止、セキュリティ、コンプライアンス」を含める(投稿制限・ブロックに使うため)
- データセーフティは**プライバシーポリシー(`release/1.1-docs` の docs/privacy_policy.md §1.4〜1.5)と一致していること**が審査で見られる。上記の表はポリシー 1.4 の表と 1:1 対応

## 2. コンテンツレーティング(IARC)

| 設問 | v1.0 | v1.1 |
|---|---|---|
| ユーザー間の交流・ユーザー生成コンテンツ | いいえ | **はい** |
| → ユーザーが生成したコンテンツを他のユーザーと共有できますか? | — | **はい**(写真のみ。テキスト投稿・チャット・DM は無し) |
| → 共有されるコンテンツはモデレーションされていますか? | — | **はい**(自動判定 + 複数ユーザー承認 + 運営の削除権限) |
| → 個人情報や位置情報の共有 | いいえ | **いいえ**(匿名ID、EXIF 除去) |
| その他(暴力・性的・不適切な言葉・規制対象物・ギャンブル・デジタル購入) | いいえ | 変更なし |

→ 「ユーザー生成コンテンツ」を「はい」にするとレーティングが「全年齢」から **「Users Interact / ユーザー同士の交流」の注記付き**になる(区分自体は変わらないことが多い)。想定: 全年齢(3+) + 「ユーザー同士の交流」ラベル。アンケートは**再提出が必要**(既存の証明書はそのまま使えない)

### Google Play UGC ポリシー対応(審査官への説明用メモ。フォームに直接の設問は無いが、レビュー時の問い合わせに備える)

| 要件 | 実装 |
|---|---|
| 利用規約への同意 | 初回共有時にダイアログで規約(第3条の2)を表示し、同意を `CommunityService.consent` で記録。未同意では送信されない |
| アプリ内の通報 | 採用写真の出典表記横「…」/ アイテム長押し / 承認カードのメニュー → 理由選択(`showReportReasonSheet`) |
| ブロック | 投稿者単位で非表示(`blocks` テーブル + 端末キャッシュ)。マイページで解除 |
| モデレーション | Edge Function `judge-photo`(不適切・一致度・画質)→ 他ユーザー3人承認 → 通報3件で自動保留 → 運営が `npx supabase db query` で最終判断 |
| 違反者への対処 | `posters.blocked` で投稿停止 |
| 削除手段 | 本人の取り消し(アプリ内)、権利者・本人からのメール窓口(プライバシーポリシー 1.5 / 4) |
| 未成年保護 | ターゲット 13歳以上。顔写り込みは規約で禁止 + 自動判定で顔検出時は減点 |

### 権限(Manifest)
- v1.1 で追加: `POST_NOTIFICATIONS` / `RECEIVE_BOOT_COMPLETED`(発売通知)。データセーフティの対象外。Play の「権限の申告」フォームで説明を求められる特別な権限(SMS・通話・位置情報・全ファイルアクセス等)ではない
- カメラ・ストレージ権限は image_picker の Photo Picker / カメラ Intent 経由なので Manifest に権限を持たない

## 4. ストア掲載文の修正箇所(`store_listing.md` §1 の v1.1 版)

- 簡単な説明(80字): 変更なしでも可。写真共有を訴求するなら「主要メーカーの新作を横断チェック。獲得・ダブり・支出を記録し、写真でみんなの図鑑を作ろう!」(約50字)
- 詳しい説明:
  - 【コレクション管理】に追記: 「・獲得したアイテムにメモや回した場所を残せます」
  - 【新作チェック】の「発売が近づくとホームに表示されます」→「発売が近づくとホームに表示され、発売日の朝に通知でお知らせします」、「・作品名タグで好きな作品のガチャをメーカー横断でまとめて探せます」
  - 新セクション【みんなの図鑑(写真共有)】: 「・撮った写真を「みんなの図鑑」に共有すると、審査を経て他のユーザーの図鑑画像として使われます / ・気に入った写真にいいね。不適切な写真は通報・非表示にできます / ・共有は写真ごとに任意。共有しない写真は端末から出ません」
  - 「■ 安心してお使いいただけます」の **「コレクションの記録・写真はすべて端末内にのみ保存され、外部に送信されません」** を **「コレクションの記録は端末内に保存されます。写真は「みんなの図鑑」への共有を選んだものだけがサーバーに送信されます(位置情報などは除去)」** に変更(現行文のままだとデータセーフティと矛盾)
- スクリーンショット: 承認カード・いいね・クレジット表記が入った画面を1枚追加すると UGC 機能の説明になる(任意。DEMO_MODE で投稿写真はダミー描画になるので公式画像は入らない)

## 5. v1.1 提出の順序

1. `release/1.1-docs` を main にマージ、改定日を実日付にして push → Pages で公開されたことを確認(プライバシーポリシー URL は同じなのでフォーム変更不要)
2. Play Console: データセーフティを §1 の通り更新 → IARC アンケート再提出(§2) → 「アプリのコンテンツ」で保存
3. ストア掲載文を §4 で更新
4. 本番トラックに v1.1 AAB(`release/gacha_pocket_v1.1.0_<sha>.aab`)+ `store/release_notes.txt` をアップロード。段階的公開(20%→50%→100%)推奨
5. Supabase 側: `judge-photo` の `MATCH_MODEL_API_KEY` / `GOOGLE_VISION_API_KEY` は任意。未設定でも一致度0.5固定で運用可
